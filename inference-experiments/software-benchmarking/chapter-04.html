4장 개요

모델은 답변을 어떻게 쓰나

학습을 마친 모델에 질문을 넣어 답을 얻는 과정을 추론이라고 한다.

예제 질문

“12에서 5를 빼면 몇 개야?”

화면에는 글자가 보인다. 모델은 글을 일정한 규칙으로 나눈 단위인 토큰을 번호로 바꿔 읽는다. 한 단어가 여러 토큰이 될 수도 있다.

다음 토큰 선택

모델은 질문과 지금까지 쓴 답을 보고 다음에 올 토큰의 점수를 계산한다. 선택한 토큰을 답 끝에 붙이고 같은 계산을 반복한다.

이 계산에 쓰는, 학습으로 정한 수가 가중치다. Gemma 4 31B IT의 31B는 매개변수 약 310억 개, IT는 지시를 따르도록 추가 학습했다는 뜻이다.

4장 개요

첫 토큰이 나오기까지

“KV 캐시를 한 문장으로 설명해 줘.”라는 요청을 보냈다고 하자.

01

입력 준비

대화 템플릿은 질문과 답변의 시작 위치를 표시하는 양식이다. 서버가 이 양식에 질문을 넣고, 토크나이저가 글을 토큰 번호로 바꾼다.

02

프리필 Prefill

모델이 질문 전체를 읽는다. 나중에 다시 참고할 입력의 계산값을 저장한 뒤, 답의 첫 토큰을 선택한다.

03

디코드 Decode

저장해 둔 계산값으로 앞의 내용을 참고해 토큰을 하나씩 더 쓴다. 이때 재사용하는 키(Key)와 값(Value)의 저장 공간을 KV 캐시라고 한다.

첫 토큰이 늦게 도착하는 경우와 첫 토큰 이후 답변이 천천히 이어지는 경우는 측정 구간이 다르다.

4.1 · CUDA와 커널

커널은 GPU에서 실행하는 함수다

CUDA는 개발자가 NVIDIA GPU에 계산을 맡길 때 사용하는 프로그래밍 환경이다.

각 수에 1을 더하는 예

위치첫째둘째셋째
입력379
계산3 + 17 + 19 + 1
출력4810

누가 어느 값을 계산할까?

CPU가 커널을 호출하면 GPU는 같은 함수의 작업을 여러 개 실행한다. 작업 하나를 스레드라고 한다. 여기서는 각 스레드가 배열의 한 위치를 맡는다.

각 위치는 다른 위치의 결과를 기다릴 필요가 없다. GPU는 이런 계산을 동시에 많이 수행할 수 있다.

4.1 · CUDA

GPU는 행렬곱을 어떻게 실행하나

선형층의 계산

Y = XW + b

행렬은 수를 행과 열로 배열한 표다. 선형층은 입력 표 X와 가중치 표 W를 곱하고, 정해 둔 값 b를 더한다. 예를 들어 입력 [2, 3], 가중치 [4, 1], b = 1이면 출력은 2×4 + 3×1 + 1 = 12다.

cuBLAS
행렬곱(GEMM)을 실행하는 함수가 들어 있다. cuDNN에는 신경망에 자주 쓰이는 연산이 들어 있다.
CUTLASS · CuTe
행렬을 어떤 크기로 나누고 GPU에 어떻게 배치할지 조정해 커널을 만드는 도구다.
커널 선택
같은 행렬곱도 행·열 수와 GPU에 따라 빠른 구현이 다르다. 보통 프레임워크나 엔진이 맞는 커널을 고른다.

4.1 · 커널 융합

중간 배열을 저장하는 비용

수 1,024개에 각각 1을 더한 뒤 음수만 0으로 바꾼다(ReLU). 수 하나는 4바이트(FP32)다. 두 계산을 한 커널에서 처리하는 기법이 융합이다.

두 커널로 실행

16 KiB

입력 읽기 → 중간 배열 쓰기 → 중간 배열 읽기 → 출력 쓰기. 배열 하나는 4 KiB다.

한 커널로 실행

8 KiB

입력을 읽고 두 계산을 이어서 한 뒤 결과만 쓴다. 중간값은 연산 중 잠깐 쓰는 GPU 내부 저장 공간(레지스터)에 둔다.

1 KiB는 1,024바이트다. 예제는 캐시 효과를 제외하고 배열 접근량을 계산했다. 실제 실행 시간은 메모리 대기, 커널 호출 비용과 연산량에도 영향을 받는다.

4.2 · 딥러닝 프레임워크

PyTorch가 실행하는 연산

프레임워크는 모델 계산을 코드로 적고 실행하는 데 쓰는 도구다. PyTorch에서는 여러 수를 담은 배열을 텐서라고 부른다.

def activate(x):
    return (x + 1).relu()

fast_activate = torch.compile(activate)
with torch.inference_mode():
    y = fast_activate(x)

x는 GPU에 올라간 PyTorch 텐서다.

일반 실행
파이썬으로 덧셈과 ReLU를 적으면 PyTorch가 GPU 연산을 호출한다. 추론 모드에서는 가중치를 학습할 때 쓰는 계산 기록을 생략한다.
컴파일
컴파일은 코드를 실행하기 좋은 형태로 바꾸는 과정이다. 컴파일러는 덧셈과 ReLU를 한 커널로 합칠 수 있는지 살핀다.
측정 시점
처음 호출할 때 컴파일 비용이 들 수 있다. 준비 시간과 이후의 반복 실행 시간을 따로 잰다.

4.2 · 모델 형식과 런타임

모델 디렉터리에서 무엇을 읽나

Gemma 체크포인트

*.safetensors
학습한 가중치 텐서. 큰 모델은 여러 파일에 나뉜다.
config.json
계산 단계를 몇 층 쌓았는지와 각 층의 구조를 담는다. 엔진이 올바른 모델을 구성하는 데 쓴다.
토크나이저·대화 템플릿
문자를 토큰으로 바꾸고 사용자와 모델 발화의 경계를 표시한다.

같은 모델을 실행하는 다른 방법

계산 그래프는 연산의 순서와 연결을 나타낸다. ONNX로 이를 저장하면 ONNX Runtime으로 실행하거나, TensorRT로 NVIDIA GPU에 맞는 실행 프로그램을 만들 수 있다.

라이브러리는 불러다 쓸 수 있는 코드 모음이다. Transformers에는 언어 모델 구현이, Diffusers에는 잡음을 여러 단계에 걸쳐 줄여 이미지를 만드는 모델 등의 구현이 있다.

4.3 · 추론 엔진

vLLM, SGLang, TensorRT-LLM

추론 엔진은 모델을 실행하는 프로그램이다. 질문이 여러 개 들어오면 어느 질문을 함께 계산할지 정하고, 각 답변이 끝날 때까지 필요한 메모리를 관리한다.

엔진4장에서 살펴보는 특징검토할 상황
vLLMvllm serve로 서버를 시작하면 다른 프로그램이 정해진 형식(API)으로 질문을 보낼 수 있다.같은 모델로 여러 서빙 설정을 비교할 때
SGLang같은 문장으로 시작하는 요청끼리 이미 계산한 부분을 재사용할 수 있다.같은 문서에 여러 질문을 보내거나, 큰 모델을 여러 GPU에 나눠 실행할 때
TensorRT-LLMNVIDIA GPU와 가중치를 저장하는 수 형식에 맞춘 계산 방법을 제공한다.특정 GPU와 모델 조합에서 성능을 더 조정할 때

비교 기준은 서비스의 입력 길이, 동시 요청 수, 지연 시간 목표다. 같은 엔진도 이 조건이 달라지면 측정값이 달라진다.

4.3 · vLLM의 요청 처리

생성이 끝난 자리에 다음 요청을 넣는다

배치는 함께 계산할 요청의 묶음이다. 매 계산 단계마다 묶음의 구성원을 바꿀 수 있는 방식을 연속 배칭이라고 한다. 여기서는 두 요청이 정원이다.

요청계산 단계 1단계 2단계 3단계 4
A생성종료——
B생성생성생성종료
C대기대기프리필생성

C는 B가 끝나기 전에 들어온다. vLLM은 요청의 KV 캐시를 블록 단위로 관리한다. 접두사 캐싱을 켜면 일치하는 입력 블록의 프리필 결과도 다시 쓸 수 있다.

4.3 · 실습 장비

H100 네 장으로 모델 한 개 실행하기

텐서 병렬 크기(TP)를 4로 설정하면 한 요청의 층 연산에 네 GPU가 함께 참여한다.

BF16은 한 수를 2바이트로 저장하는 형식이다. 310억 개 매개변수를 BF16으로 저장하면 가중치는 약 62 GB다. 균등 분할만 가정하면 GPU당 약 15.5 GB다. 실제 사용량에는 복제되는 텐서, KV 캐시, 작업 공간, DFlash 가중치가 더해진다.

4.4 · NVIDIA Dynamo

어느 워커로 요청을 보낼까

워커는 요청을 계산하는 프로그램이고, 라우터는 요청을 받을 워커를 고르는 프로그램이다. Dynamo는 여러 워커의 일을 나눠 주는 분산 서빙 소프트웨어다.

라우팅

캐시가 있는 워커

워커 A가 문서 앞부분을 이미 처리했다면, 같은 문서의 두 번째 질문을 A에 보낼 때 계산을 줄일 수 있다. A에 대기 중인 요청 수도 함께 고려한다.

프리필·디코드 분리

입력과 출력 담당

한 그룹이 질문을 읽고, 다른 그룹이 답을 이어 쓴다. 앞 그룹이 계산한 KV를 뒤 그룹에 보내야 하므로 전송 시간이 든다.

용량 조정

단계별 워커 수

긴 문서가 몰리면 입력을 읽는 워커가 부족할 수 있다. 어느 단계에서 요청이 기다리는지 보고 각 그룹의 워커 수를 조정한다.

실습은 단일 노드에 vLLM 엔진 하나를 띄운다. 이때 네 GPU 사이의 분할은 vLLM의 텐서 병렬 설정이 담당한다.

4.5 · 성능 벤치마킹

지연 시간과 처리량의 측정 구간

벤치마크는 조건을 정해 성능을 재는 실험이다. 지연 시간은 한 사람이 기다린 시간이고, 처리량은 서버 전체가 일정 시간에 끝낸 작업량이다.

지표실습의 정의무엇을 알 수 있나

첫 토큰 뒤 90 ms 동안 9개가 더 나오면 TPOT는 10 ms/토큰이다. Gemma 노트는 서버 내부 TTFT를 읽고, 기존 H100·B300 노트는 요청을 보낸 때부터 첫 토큰을 받은 때까지 잰다.

4.5 · 부하 테스트

어떤 요청을 얼마나 겹쳐 보낼까

부하 테스트는 요청을 실제로 보내고, 동시에 여러 사람이 쓸 때 얼마나 기다리는지 재는 실험이다.

문서 질의응답 서비스의 예

같은 문서에 대한 질문 100개와 서로 다른 문서에 대한 질문 100개는 서버에 다른 부하를 준다.

길이가 같아도 접두사 재사용 기회가 다르다. 코드 완성과 자유 서술은 초안 토큰이 채택되는 비율도 달라질 수 있다.

입력 분포
입력·출력 길이, 질문 내용, 샘플링 설정을 맞춘다. 실제 요청을 복제한 트래픽이나 대표 예제를 쓸 수 있다.
부하 패턴
동시 요청 4개는 최대 네 사람이 답을 기다리는 상태다. 준비 요청(워밍업)을 먼저 보내고, 본 측정에서 가운데 값(p50)과 느린 쪽의 값(p95)을 본다.
측정 도구
vLLM의 서빙 벤치마크나 GenAI-Perf로 토큰 지표를, Locust로 서비스 이용 패턴을 측정할 수 있다.

4.5 · 성능 프로파일링

지연이 늘어난 구간을 찾는 방법

프로파일링은 프로그램 속 어느 작업에 시간이 들었는지 재는 방법이다. 먼저 벤치마크에서 느려진 구간을 찾고, 그 구간을 더 자세히 본다.

PyTorch Profiler
어떤 연산에 CPU·GPU 시간이 집중되는지 찾는다. 작은 연산이 여러 번 호출되면 융합 후보를 살펴본다.
Nsight Systems
CPU 호출, GPU 작업, GPU 간 통신을 한 타임라인에서 본다. 텐서 병렬 실행 중 GPU가 통신을 기다리는 구간을 찾을 수 있다.
Nsight Compute
특정 CUDA 커널의 메모리 접근과 연산기 사용률을 조사한다. 중간 배열을 읽고 쓰는 비용을 확인할 때 적합하다.

커널을 바꿨다면 원래 부하 테스트를 다시 실행한다. 그 커널에서 줄어든 시간이 사용자 응답 시간에도 나타나는지 확인한다.

실습 연결 · 4.3 추측 디코딩

DFlash가 제안하고 Gemma가 검증한다

보통 Gemma는 한 단계에서 다음 토큰 하나를 정한다. DFlash는 Gemma가 앞서 계산한 중간값을 보고 다음 토큰 여러 개를 미리 제안한다. Gemma는 한 번의 모델 계산으로 후보들을 검증한다.

각 위치에서 최고 점수 토큰을 고르는 예

기호 하나를 토큰 하나로 가정한다.

초안 ABCD

확정 ABX
