# LLM 채점의 답변 순서 평가

[evaluate.ipynb](evaluate.ipynb)에서 같은 질문과 답변 두 개를 순서만 바꿔 채점한다. OpenAI Responses API로 판정하고 Python으로 기준 판정 일치율과 선택 변경률을 계산한다. Evals API와 외부 평가 프레임워크는 사용하지 않는다.

Python의 리스트·딕셔너리와 Jupyter 노트북 사용법을 알고 있어야 한다. 새 채점을 실행하려면 OpenAI API 키가 필요하다.

## 평가 설계

| 항목 | 내용 |
| --- | --- |
| 목적 | 제시 순서가 바뀌어도 같은 답변을 선택하는지, 선택이 기준 판정과 일치하는지 확인 |
| 입력 | 질문, 답변 A, 답변 B |
| 문항 | 산술, 조건 경계, 독해, 정보 부족, 지시 준수, Python 기초 등 20개 |
| 기준 판정 | A 우위 8개, B 우위 8개, 동등 4개 |
| 방법 | 문항마다 A→B와 B→A를 별개의 요청으로 채점. 총 40회 호출 |
| 출력 | `first`, `second`, `tie` 중 하나와 한국어 한 문장의 판정 근거 |
| 예제의 점검 목표 | 기준 판정 일치율 100%, 선택 변경률 0% |

[OpenAI 평가 설계 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices)의 목적·데이터·지표 정의, 답변 쌍 비교, 사람의 검토 절차를 적용한다. 출력 형식은 Structured Outputs로 제한한다. 형식이 맞는 것과 판정이 정확한 것은 별개로 평가한다.

[data/cases.json](data/cases.json)의 `expected`와 `explanation`은 기준 판정과 그 설명이다. 모델에는 이 두 필드를 보내지 않고 질문과 두 답변만 보낸다. 요청 간 대화 이력은 공유하지 않는다. 순서를 바꿀 때 답변 내용과 채점 지시는 유지한다.

문항과 기준 판정은 이 실습용으로 작성한 예제이며, 독립적인 사람 검토가 완료된 벤치마크는 아니다. 결과를 해석하기 전에 사람이 원문과 기준 판정을 확인한다. 동일한 정답, 표현이 다른 동등한 답변, 동일한 오답을 포함한다. **`tie`는 두 답변이 동등하다는 뜻이며, 둘 다 정답이라는 뜻은 아니다.**

## 설치

저장소 루트에서 다음 명령을 실행한다. 이미 이 실습의 가상환경이 있다면 생성 명령은 생략한다.

```powershell
cd evaluation/openai-eval
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m jupyterlab evaluate.ipynb
```

Python 3.12.3에서 확인했다. 직접 사용하는 패키지의 버전은 [requirements.txt](requirements.txt)에 고정했다. 기본 채점 모델은 `gpt-6-luna`이며, 노트북의 `MODEL`에서 변경한다.

이 폴더의 `.env`에 `OPENAI_API_KEY`를 설정한다. [.env.example](.env.example)은 변수 이름만 제공한다. 이미 `.env`를 준비했다면 그대로 사용한다. 키는 결과와 노트북 출력에 저장하지 않는다. 기존 프로세스에 같은 환경 변수가 설정되어 있으면 `load_dotenv`의 기본 동작에 따라 그 값이 우선한다.

VS Code에서도 설치한 가상환경의 Python 커널을 선택해 실행할 수 있다. 작업 디렉터리는 `evaluation/openai-eval`로 둔다.

## 실행

| 노트북 단계 | 내용 | API 호출 |
| --- | --- | --- |
| 1. 설정 | 패키지, 모델, 결과 경로, 채점 지시, 출력 형식 정의 | 없음 |
| 2. 문항 확인과 채점 함수 | 문항 표시와 함수 정의 | 없음 |
| 3. 새 채점 실행 | 문항 20개를 두 순서로 채점하고 저장 | 40회 |
| 4. 저장된 결과 집계 | 비율과 문항별 판정 표시 | 없음 |
| 5. 불일치 사례 확인 | 선택 변경 또는 기준 판정 불일치 사례의 답변과 근거 표시 | 없음 |

새 채점을 실행할 때는 위 순서대로 실행한다. 3단계만 API를 호출하며 토큰 사용량에 따른 비용이 발생한다. 모델의 출력과 SDK 기본 동작에 따라 실제 요청 수와 비용이 달라질 수 있다. 문항 수를 바꾸면 기본 호출 수는 문항 수의 두 배가 된다.

저장된 결과를 읽을 때는 **1단계, 4단계, 5단계만 실행**한다. 이 과정에는 API 키가 필요 없다. 4단계는 현재 문항 파일 대신 결과에 저장된 문항과 기준 판정을 사용한다.

기본 결과 경로는 `results/judgments.jsonl`이다. 결과 파일이 이미 있으면 3단계는 API를 호출하기 전에 `FileExistsError`로 중단한다. 새 실험은 1단계의 `RESULTS`를 다른 파일명으로 변경한 뒤 실행한다.

모델과 SDK의 생성 옵션은 기본값을 사용한다. API 오류나 파싱할 수 없는 응답을 `tie` 또는 성공으로 처리하지 않는다. 오류가 발생하면 실행이 중단되고, 두 순서의 채점이 완료된 문항만 결과에 남는다. 중단된 실행을 자동으로 이어서 수행하지 않는다.

## 결과 파일

JSONL 한 줄이 문항 하나이며, 두 순서의 판정을 함께 저장한다.

| 필드 | 내용 |
| --- | --- |
| `model` | 요청에 사용한 채점 모델 이름 |
| `question`, `a`, `b` | 실행에 사용한 질문과 원래 답변 |
| `expected`, `explanation` | 기준 판정과 설명. 모델 입력에서 제외 |
| `ab` | A→B 순서의 `choice`, `reason` |
| `ba` | B→A 순서의 `choice`, `reason` |

집계는 이 파일에서 계산하며 별도의 집계 파일을 만들지 않는다. 한 문항을 완료할 때마다 저장하므로 중간에 실행이 중단되어도 완료한 문항을 분석할 수 있다. 집계에 표시되는 문항 수가 20개인지 확인한다. 빈 결과 파일은 집계할 수 없다.

## 지표 해석

| 지표 | 계산 |
| --- | --- |
| 기준 판정 일치율 | 원래 답변으로 복원한 선택이 `expected`와 같은 판정 수 ÷ 전체 판정 수 |
| 선택 변경률 | 두 순서에서 복원한 선택이 다른 문항 수 ÷ 저장된 문항 수 |
| 첫 번째 선택률 | `first` 판정 수 ÷ `tie`를 제외한 판정 수 |
| 동등 판정 비율 | `tie` 판정 수 ÷ 전체 판정 수 |

비율은 백분율로 표시한다. 모두 `tie`이면 첫 번째 선택률은 계산할 수 없어 NaN으로 표시된다. A 또는 B와 `tie` 사이의 변화도 선택 변경에 포함한다.

예를 들어 A→B에서 `first`, B→A에서 `second`를 고르면 모두 원래 답변 A를 선택한 것이다. 반대로 두 순서에서 계속 `first`를 고르면 선택한 답변이 A에서 B로 바뀐 것이다. 같은 오답을 두 번 고른 경우 선택 변경률은 낮아도 기준 판정 일치율은 낮다. 두 지표를 함께 읽어야 한다.

불일치 사례는 노트북 마지막 단계에서 원문, 기준 판정, 두 순서의 선택과 근거를 함께 검토한다. 기준 판정 자체가 잘못되었다면 먼저 수정한다. 채점 지시를 수정해 다시 평가할 때는 기존 결과를 보존하고 같은 문항을 사용한다. 같은 문항으로 수정과 검사를 반복한 결과를 새로운 문항에 대한 성능으로 해석하지 않는다.

20문항의 예비 실험으로 일반적인 채점 성능을 단정할 수 없다. 각 순서에서 한 번만 요청하고 항상 A→B 다음 B→A 순서로 실행하므로, 관찰된 변화에는 생성의 변동성이나 호출 시점의 영향도 포함된다. 선택 변경률만으로 순서가 변화의 원인임을 입증하지 않는다. 답변 길이와 문체는 순서 조건 사이에서 유지하며, 이 실험으로 길이·문체의 독립적인 효과를 측정하지 않는다.

## 실행 확인과 결과

2026-11-15에 `gpt-6-luna`로 20문항의 두 순서, 총 40개 판정을 완료했다. [저장된 결과](results/judgments.jsonl)를 노트북의 1·4·5단계로 다시 읽을 수 있다.

| 지표 | 결과 |
| --- | --- |
| 기준 판정 일치율 | 100% (40/40) |
| 선택 변경률 | 0% (0/20) |
| 첫 번째 선택률 | 50% (16/32, 동등 판정 제외) |
| 동등 판정 비율 | 20% (8/40) |

이 결과는 제공된 예제 기준 판정과의 일치 정도다. 사람의 독립적인 검토와 반복 실험으로 검증된 일반 성능을 뜻하지 않는다.
